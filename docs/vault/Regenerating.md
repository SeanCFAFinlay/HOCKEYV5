# Regenerating the vault

Most of this vault is generated. Don't hand-edit generated notes — the next run
overwrites them.

```bash
npm run vault          # from src/ — runs both generators
```

or directly:

```bash
node docs/vault/tools/generate-vault.mjs      # Assets/ + media/
node docs/vault/tools/generate-codebase.mjs   # Codebase/
```

## What's generated vs. hand-written

| Path | Source of truth |
|---|---|
| `Assets/Towers,Enemies,Maps,Projectiles,Themes/` | generated from `src/js/config/` |
| `Assets/Asset Index.md` | generated |
| `media/*.svg` | generated |
| `Codebase/` | generated by parsing `src/js/**/*.js` |
| `Assets/Audio Assets.md` | **hand-written** |
| [[Home]], [[Findings]], this note | **hand-written** |
| `tools/prose.mjs` | **hand-written** — the descriptions |

The generators only delete the directories they own, so hand-written notes
placed alongside generated ones survive a regenerate.

## Where the descriptions live

`tools/prose.mjs`. Everything else in an asset note — stats, links, colours,
counts — is derived from config at generate time, deliberately, so it can't
drift. If you want to change what a tower's note *says about it*, edit
`prose.mjs`, not the note.

## What the pictures actually are

> [!important] They are schematics, not renders
> No Three.js, no lighting, no materials, no post-processing. Nothing in this
> vault was screenshotted from the running game.

`tools/recipes.mjs` transcribes the primitive lists from the real mesh builders
— every radius, height and position is copied from
[[rendering-tower-meshes|rendering/tower-meshes.js]] and
[[rendering-enemy-meshes|rendering/enemy-meshes.js]]. `tools/art.mjs` then draws
those primitives in a cabinet projection (+z toward the viewer, down-left).

Front elevation was tried first and rejected: the game models towers facing +z,
so a flat front view hides every barrel, stick and nozzle.

**What this buys you:** the silhouette, proportions, part layout and exact
colours are all faithful, and the relative sizes are true (a Boss Puck really is
~2.6x a Puck). **What it costs you:** no idea what the thing looks like lit.

Consequences worth knowing:

- **Recipes are a second copy of the geometry.** Change a mesh builder and the
  schematic silently goes stale — nothing links them at runtime. If these drift
  badly, the honest fix is headless screenshots of the real meshes, not more
  transcription.
- Randomised parts (Ice Spray's crystals, Tackle's dust, Flare's smoke) are
  re-created with a seeded RNG, so regenerating produces no diff churn.
- Towers are drawn at **level 0**. Real towers scale 8% per level and gain a
  gold star per level.
- Map images show the *declared* grid (`cols`, `rows`, `spawns`). The actual
  maze is generated at runtime by `systems/map.js` from `level-layouts.js` plus
  a seeded RNG, so the drawn paths are indicative only.

## Adding a content pack

The vault needs nothing. Add the pack to `config/themes.js` and re-run — new
towers, enemies, maps, projectiles, notes and pictures all appear. Add prose to
`tools/prose.mjs` if you want the notes to say something beyond the numbers, and
a tower recipe to `tools/recipes.mjs` if the pack has its own mesh family.

## Gotcha: directory casing

`media/` must not be a case-insensitive match for `Assets/`. This originally
used `assets/img/`, which on Windows *is* `Assets/img/` — the images silently
nested inside the notes tree and the two cleanup steps deadlocked on each other.
